## 1. 背景与目标

Orca 右侧栏的 Links 面板用于保存开发者高频访问的项目资源，例如文档、监控页、环境入口和仪表盘。能力应让用户在当前项目中快速组织、打开、调整和迁移这些链接，同时提供跨项目复用的全局链接。

- **目标用户**：在本机、folder workspace 或 SSH 项目中使用 Orca 的开发者。
- **用户问题**：项目相关 URL 分散在浏览器收藏夹、聊天记录或文档中；同类链接缺少项目内分类、排序和可迁移性。
- **产品目标**：提供本机持久化、项目隔离和全局复用的链接管理；重启后保留；在不执行远端命令、不读取远端文件的前提下，以系统默认浏览器安全打开 URL。
- **成功定义**：本需求不虚构使用量、性能或转化指标。验收以可观察的产品行为、持久化和安全边界为准。

### 2.2 不在本次范围

| 事项 | 不做原因 | 后续归属/触发条件 |
| --- | --- | --- |
| 云端同步、账号共享、多人协作 | 当前实现为本机 profile 持久化，未定义冲突解决或授权模型。 | 另立同步/协作需求。 |
| 跨 scope 拖拽移动或复制 | local 与 global 是不同存储域，现有产品没有 copy/move 交互设计。 | 先确认移动后是否保留原链接、ID 与排序。 |
| 任意协议、文件路径或命令链接 | `file:`、`javascript:`、`data:` 等会扩大本地执行或注入风险。 | 无；若未来扩展，必须单独安全评审。 |
| 链接可用性探测、预览、抓取网页元数据 | 现有产品仅保存 URL 并交给系统浏览器打开。 | 独立的网络访问与隐私设计。 |
| 远端 profile 同步或在 SSH 主机保存链接 | 违背客户端控制面与执行主机边界。 | 需要独立的远端数据所有权方案。 |

## 3. 角色与业务对象

### 3.1 角色与权限

| 角色 | 使用场景 | 可执行动作 | 可见范围 |
| --- | --- | --- | --- |
| Orca 本机用户 | 打开、管理当前项目链接 | CRUD、建立/删除文件夹、同 scope 拖拽排序、导入/导出 | 当前项目链接、全局链接 |
| Orca 本机用户 | SSH/folder workspace 中使用面板 | 读取及管理客户端 profile 中对应 repo ID 的数据 | 不读取远端文件；不代表远端用户或远端 host 执行操作 |
| 系统浏览器 | 打开链接 | 仅接收已校验 HTTP/HTTPS URL | 浏览器自身权限范围 |

本需求没有多用户权限、共享编辑或服务端 ACL；“当前项目”由 Orca 已注册的 `repoId` 定义，而非任意路径字符串。

### 3.2 关键业务对象

| 对象 | 业务含义 | 创建/来源 | 生命周期或关键状态 |
| --- | --- | --- | --- |
| 项目链接 | 归属单个项目的快捷 URL | 用户新建、编辑或导入 | 按 `repoId` 保存；删除项目最终所有者后应删除 |
| 全局链接 | 跨项目可见的快捷 URL | 用户新建或全局编辑 | `repoId=''`；不随项目删除而删除 |
| 链接分类 | 链接的层级组织路径 | 用户输入分类或拖拽移动 | 空分类为未分类；`/` 分隔层级 |
| 文件夹声明 | 没有链接时仍应显示的分类路径 | 用户创建或导入 | 与链接独立；删除仅删除声明，不隐式删除链接 |
| 导出文件 | 用户选择位置写出的迁移文件 | 导出操作 | 带 kind、schemaVersion、链接和文件夹；不携带原 ID/时间戳 |

## 4. 用户场景与产品行为

### S1：在当前项目创建并打开链接

- **关联需求与优先级**：R1、R4 / P0。
- **目标与触发**：用户在已激活项目的右侧 Links 面板选择“新建链接”。
- **前置条件**：当前 `repoId` 已在 Orca Store 注册。
- **主流程**：
  1. 用户填写名称、URL 和可选分类；UI 对名称、分类、URL 长度做输入限制。
  2. 系统提交到主进程；主进程确认 repo 存在，规范化名称、分类和 URL。
  3. 成功保存后，当前项目的链接列表按手工排序再名称显示。
  4. 用户点击行或“打开链接”，URL 经 shell IPC 在系统默认浏览器打开。
- **完成结果**：链接重启后仍属于当前项目；不会出现在其他项目的 local 列表。
- **关键分支**：
  - 无活动项目：Links 面板显示空状态，不应对不存在的 repo 进行写入。
  - 名称为空、URL 为空、URL 无法解析、协议非 HTTP/HTTPS 或超过长度：拒绝保存并保留用户可修正输入。
  - 主进程返回错误：renderer 保留或回滚乐观状态，并展示失败反馈。

### S2：以文件夹和拖拽整理链接

- **关联需求与优先级**：R3 / P0。
- **目标与触发**：用户希望将链接组织为如“生产/数据库”的层级，或调整同一分类中的顺序。
- **前置条件**：用户位于 local 或 global 的一个 scope。
- **主流程**：
  1. 用户创建顶级或子文件夹；产品拼接父路径和新名称。
  2. 系统将路径按 `/` 规范化，空段被去除；有效路径最多 5 层，每段最多 40 个字符。
  3. 即使文件夹暂时没有链接，树仍显示该文件夹。
  4. 用户在同一 scope 内拖拽链接，产品重编号目标分类内的 `order`，必要时更新被拖拽链接的分类。
- **完成结果**：树以分类路径显示，未分类链接平铺于“未分类”分组；拖拽后的顺序在重启后保留。
- **关键分支**：
  - 重复创建相同路径：不应重复持久化文件夹。
  - 跨 local/global scope 拖拽：当前行为是忽略，不产生复制或移动。
  - 删除文件夹：只删除空文件夹声明；分类相同的链接仍保留并可由链接隐含树节点显示。

### S3：管理全局链接

- **关联需求与优先级**：R2、R3 / P0。
- **目标与触发**：用户在管理对话框或空白区域菜单中选择全局 scope。
- **前置条件**：Orca 有活动项目以显示 Links 面板；全局数据本身不依赖特定 repo。
- **主流程**：
  1. 用户切换“Global”标签，新增、编辑、删除全局链接或文件夹。
  2. 系统在 global 持久化记录中保存链接，并使用 `repoId=''` 标记。
  3. Links 面板将 global 树标记为“Global (all projects)”，与当前项目树分开显示。
- **完成结果**：全局链接在本机各项目间复用；项目删除不会清理 global 数据。

### S4：导出与导入项目链接

- **关联需求与优先级**：R5、R4 / P1。
- **目标与触发**：用户需要迁移、备份或从先前导出恢复当前项目链接。
- **前置条件**：导入目标 repo 存在；用户在原生文件对话框选择文件。
- **主流程**：
  1. 导出时，系统获取当前项目的链接和文件夹，提示保存 `.orca-links.json`。
  2. 导出文件携带 `kind='orca-project-links'`、schemaVersion、导出时间、链接字段和文件夹路径；不复制原 ID、创建时间或更新时间。
  3. 导入时，系统读取 JSON、验证 envelope 和 schema 兼容性，并用手工保存相同的链接名称/URL/分类规范化规则处理每项。
  4. 有效链接按规范化后的 `(url, category)` 与现存数据及导入批次去重；新链接重新分配 ID 和时间戳。
  5. 成功后刷新该 repo 的链接与文件夹缓存并反馈导入/跳过数量。
- **关键分支**：
  - 用户取消文件对话框：无数据改变，不显示失败。
  - 非 JSON、非 Orca envelope 或 schemaVersion 缺失：拒绝整个文件。
  - 导入文件版本高于当前支持版本：拒绝整个文件，提示更新 Orca。
  - 单条链接格式错误或协议不安全：跳过该条，保留其他有效条目。
  - 现有实现对导入 folder 仅 trim/filter，未与手工创建使用同一层级/长度规范化；该差异列为待决策和待修复项。

### S5：项目删除与远程边界

- **关联需求与优先级**：R6、R7 / P0。
- **目标与触发**：用户移除某项目，或启动时 Store 发现无注册 repo 的历史残留。
- **主流程**：
  1. 若同一 repo ID 仍在另一 execution host 注册，项目范围数据必须保留。
  2. 仅在该 repo ID 的最后一个注册记录被移除时，删除项目链接和项目文件夹记录。
  3. 启动扫残留时，不能仅因远端 `runtime:*` host 未出现在本机 catalog 就推断其项目被删除。
- **完成结果**：删除后项目范围数据不残留；global 数据保持；远端执行状态不被链接能力推断或改变。

## 5. 业务规则

| 编号 | 条件/触发 | 处理结果 | 例外与优先级 | 依据/确认状态 |
| --- | --- | --- | --- | --- |
| BR1 | 保存名称 | trim 后不能为空，最长 80。 | 不合法则拒绝保存。 | 已由现有规范化实现。 |
| BR2 | 保存分类 | trim 后可为空，最长 40。 | 空分类显示为未分类。 | 已由现有规范化实现。 |
| BR3 | 保存 URL | 裸 host 自动补 `https://`；仅允许 `http:`/`https:`；最长 2048。 | `file:`、`javascript:`、`data:` 等一律拒绝。 | 已由现有规范化及 shell 双重校验实现。 |
| BR4 | 链接显示排序 | `order` 升序；缺失 `order` 排在最后；同 order 按 `name.localeCompare`。 | 重排只影响请求中出现的 ID。 | 已由 persistence/renderer 实现。 |
| BR5 | 文件夹路径 | `/` 分段、trim、空段删除；最多 5 层、每段最多 40。 | 仅当前手工新增路径已执行该规范化。 | 导入一致性待确认。 |
| BR6 | 导入链接去重 | 以规范化 `(url, trimmed category)` 为键。 | 同 URL、不同分类是不同链接；文件内重复与既存重复分别计数。 | 已由现有 merge 实现。 |
| BR7 | 导出迁移 | 不携带 ID 和时间戳。 | 导入新建记录重新生成 ID/时间。 | 已由现有格式定义。 |
| BR8 | 删除 repo | 仅最后一个 host 的同 repo ID 消失时清理 repo-scoped 数据。 | `runtime:*` 的本地缺席不是删除证据。 | 清理遗漏已发现，待修复。 |
| BR9 | 打开 URL | renderer 只能调用 preload；shell 再次解析并只打开 HTTP/HTTPS。 | 无效或非允许协议静默拒绝 shell 打开。 | 已有安全边界。 |
