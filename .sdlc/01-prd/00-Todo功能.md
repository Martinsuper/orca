# Todo 功能需求文档（PRD）

> 需求名称：Todo功能
> 日期：2026-09-10
> 状态：已澄清
> 关联：（暂无）

---

## 1. 需求背景与目标

**一句话价值**：在 Orca 右侧栏提供对齐 Microsoft To Do 核心体验的本地任务管理能力，让开发者可在当前工作区内规划列表、管理任务与按日推进工作。

**要解决的问题**：现有 Orca 缺少与项目上下文结合的任务管理能力，用户只能记录轻量待办，无法按列表组织任务、安排日期提醒、聚焦当天工作或拆解任务步骤，容易遗漏和失去优先级。

**核心目标**：
- 在右侧栏提供 Todo Tab，支持全局与当前项目两类任务和列表。
- 提供自定义列表、任务 CRUD、重要标记、截止日期、单次提醒、一级步骤和每日工作计划。
- 提供「我的一天」「重要」「计划内」「全部」智能视图，帮助用户按场景查看任务。
- 数据仅在本机持久化；重启后保留，项目数据按 worktree 隔离。

## 2. 功能列表

### 2.1 Todo Tab

**描述**：在右侧栏活动栏中，于 Project Links 后新增 Todo Tab，承载全部 Todo 功能。

| 属性 | 值 |
|---|---|
| 显示名称 | Todo |
| 图标 | ClipboardList |
| 位置 | Project Links 之后（内置 Tab 末尾、插件 Tab 之前） |
| 可见性 | 所有 workspace 类型可见，包括 git worktree、folder workspace、SSH |

**主要流程**：用户点击 Todo 图标后进入 Todo 面板；切换到其他 Tab 后再切回，应保留当前查看的列表或视图状态。

**异常处理**：Todo 面板不可用时不得影响其他右侧栏 Tab 的正常使用。

### 2.2 全局与项目范围

**描述**：用户可管理全局和当前项目两类列表及任务。

- 全局列表和其中的任务在本机任意工作区可见。
- 项目列表和其中的任务仅在所属 worktree 中可见，不得串项目。
- 无活跃 worktree 时，用户仍可使用全局范围；项目范围展示未选择项目的空状态。
- 切换 worktree 后，项目范围立即切换为新项目的数据。

### 2.3 自定义列表

**描述**：用户可在全局或当前项目范围内创建、重命名和删除自定义列表，用于组织任务。

**输入**：列表名称，以及列表所属范围（全局或当前项目）。

**输出**：创建或更新后的列表；列表内展示其任务。

**主要流程**：
1. 用户在全局或当前项目范围内创建列表，列表名称不能为空。
2. 用户可重命名列表，名称不得为空。
3. 用户可进入某个列表查看和管理其任务。
4. 用户删除空列表时，列表从对应范围移除。
5. 用户删除含任务列表时，先展示明确的二次确认，说明该列表和其任务将一并删除；确认后才执行删除。

**异常处理**：名称为空时不允许保存；取消确认或确认超时后不删除数据。

### 2.4 任务信息与新增编辑

每条任务包含标题、备注、所属列表、完成状态、创建时间、更新时间、重要标记、截止日期、单次提醒时间、是否加入「我的一天」、一级步骤和归档状态。

**描述**：用户可在列表中创建、编辑和删除任务。

**主要流程**：
1. 用户在某个列表中输入必填标题，可选填写备注、标记重要、设置截止日期、设置一次提醒、添加步骤或加入「我的一天」。
2. 保存后，新任务出现在所属列表，初始状态为未完成。
3. 用户可修改未完成或已完成任务的上述信息。
4. 用户删除任务时，先进行轻量二次确认，确认后从列表和相关智能视图移除。

**异常处理**：标题为空时不允许保存；日期或提醒时间无效时提示用户重新选择；取消删除确认后保留任务。

### 2.5 任务步骤

**描述**：每项任务可维护多个无嵌套的一级步骤，帮助用户拆解工作。

**主要流程**：
1. 用户在任务详情或编辑态添加、编辑、勾选和删除步骤。
2. 步骤完成状态独立于任务完成状态展示。
3. 已完成步骤保持可见，用户可取消完成。

**范围限制**：步骤不支持继续嵌套为多级子任务。

### 2.6 完成与归档

**描述**：用户可切换任务完成状态；完成任务默认从普通列表和智能视图中移出并归档。

**主要流程**：
1. 用户勾选未完成任务后，任务进入归档状态。
2. 默认列表和智能视图不展示归档任务。
3. 用户可在归档视图中查看已完成任务，并可取消完成；取消完成后任务恢复到原所属列表及适用的智能视图。

### 2.7 我的一天

**描述**：「我的一天」用于聚焦用户当天主动选择处理的任务。

**主要流程**：
1. 用户可从任意未完成任务将其添加到「我的一天」，也可随时移除。
2. 「我的一天」展示当天被手动加入且未完成的任务，可跨列表查看。
3. 日期进入下一天时，「我的一天」自动清空；任务本身、所属列表、日期和其他信息保持不变。
4. 当天到期任务不自动加入「我的一天」。

### 2.8 重要、计划内和全部智能视图

**描述**：面板提供以下内置智能视图，汇总符合条件的未完成任务：

| 视图 | 展示规则 |
|---|---|
| 我的一天 | 当天手动加入的未完成任务 |
| 重要 | 被标记为重要的未完成任务 |
| 计划内 | 已设置截止日期的未完成任务，逾期任务需明显区分 |
| 全部 | 所有范围内的未完成任务 |
| 已完成 | 已归档的完成任务 |

用户可在列表和智能视图间切换；智能视图只改变查看方式，不改变任务所属列表。

### 2.9 截止日期、提醒与逾期状态

**描述**：用户可为任务设置截止日期和一次提醒，以避免遗漏。

**主要流程**：
1. 用户可单独设置截止日期、单独设置一次提醒，或同时设置两者。
2. 到达提醒时间时，用户收到本机系统通知。
3. 截止日期已过且任务未完成时，任务在所属列表和「计划内」中以明确的逾期状态展示。
4. 任务完成、删除截止日期或修改为未来日期后，不再展示逾期状态。

**异常处理**：系统通知不可用或用户拒绝通知权限时，任务仍应保留截止日期和逾期展示；不重复发送已触发的单次提醒。

## 3. 非功能需求

| 维度 | 目标值 |
|---|---|
| 响应性能 | 列表或智能视图加载、创建、编辑、完成等操作应无明显感知延迟，目标 P99 < 100ms |
| 数据可靠性 | 列表、任务、步骤、日期、提醒和归档状态在应用重启后不丢失 |
| 隔离性 | 项目列表和任务切换 worktree 后不得串项目；全局数据在本机各工作区保持一致 |
| 并发安全 | 多个 Orca 窗口操作同一份本地 Todo 数据时不得造成数据损坏或静默丢失 |
| 提醒可靠性 | 已授权系统通知时，单次提醒应在设定时间触发；通知不可用时不影响任务数据与逾期提示 |
| 兼容性 | 既有用户升级后原有 Todo 数据应继续可用；缺少新字段的旧数据按未设置处理 |

## 4. 范围外事项

以下能力不属于本次需求：

- 跨设备或云端同步、账号登录和冲突处理。
- 共享列表、成员协作、任务分配与「已分配给我」视图。
- 列表分组或文件夹层级。
- 重复任务、重复提醒和循环计划。
- 多级子任务。
- 标签、自定义分类、附件和文件关联。
- 手动拖拽排序、任务搜索、筛选和批量操作。
- Todo 数据导入、导出、备份和恢复。
- 与 Project Links 或外部任务服务的联动。

## 5. 验收标准

- [ ] 右侧栏在 Project Links 后展示 Todo Tab，且所有 workspace 类型均可访问。
- [ ] 用户可在全局和当前项目范围分别创建、重命名、删除自定义列表；全局列表跨本机工作区可见，项目列表按 worktree 隔离。
- [ ] 删除含任务的列表时必须二次确认，确认后列表及其任务一并删除；取消则不删除。
- [ ] 用户可在列表中新增、编辑、删除任务，并设置标题、备注、重要标记、截止日期、单次提醒和所属列表。
- [ ] 用户可为任务维护多个一级步骤，并独立切换每个步骤的完成状态。
- [ ] 用户完成任务后，该任务默认进入已完成视图且不再出现在普通列表和未完成智能视图；取消完成后恢复。
- [ ] 用户可手动将任务加入或移出「我的一天」；进入下一天后该视图自动清空而任务本身保留。
- [ ] 「重要」「计划内」「全部」「已完成」视图按各自规则正确汇总任务，且不改变任务所属列表。
- [ ] 提醒时间到达时，在系统通知已授权的情况下用户收到一次本机通知；未授权时任务仍正确显示。
- [ ] 未完成且截止日期已过的任务有清晰逾期标记；完成任务或调整日期后该标记更新。
- [ ] 切换 worktree 后项目列表、任务和智能视图不串项目；无活跃项目时全局范围仍可用。
- [ ] 应用重启后全局和项目数据、列表、任务、步骤、日期、提醒和完成状态均保留。
- [ ] 多窗口操作同一份 Todo 数据后不发生数据损坏或静默丢失。
